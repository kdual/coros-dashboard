# 개인 COROS 서버

공개 GitHub Pages는 정적 앱을 제공합니다. 개인 모드에서는 같은 빌드를 이 컴퓨터의 서버에서 열고 소유자로 로그인합니다.

## 실행

Node.js 22.18 이상에서 프로젝트 루트의 프런트엔드를 빌드한 후 다음 명령을 실행합니다.

```sh
npm ci
npm run build
node server/start.mjs
```

1. 터미널을 열어 둔 채 [개인 대시보드](http://127.0.0.1:4178/)에 접속합니다.
2. 개인 데이터 화면에 터미널에 표시된 소유자 로그인 코드를 입력합니다. 서버를 재시작하면 코드가 바뀝니다.
3. 이 작업에서 준비한 스냅샷은 같은 Windows 사용자로 실행할 때 로그인 후 열립니다. 프로젝트를 다른 컴퓨터로 복사한 경우 **COROS 연결**을 선택합니다.
4. COROS 로그인 화면에서 계정에 접근할 권한을 승인합니다. 대시보드로 복귀하면 서버가 첫 조회를 실행합니다. 이후 서버가 실행 중일 때 15분 간격으로 조회합니다. 코드 배포와 시계의 앱 동기화는 독립적으로 이루어집니다.
5. 로그아웃하면 개인 화면 접근이 차단됩니다. 연결 해제 시 앱이 보관한 토큰과 데이터, 사용자 계획 및 목표가 삭제됩니다. COROS 자체 권한 철회는 해당 계정의 연결 앱 설정에서 수행합니다.

## 저장 위치와 권한

서버는 IPv4 루프백 주소의 4178 포트에만 바인딩합니다. 임의 호스트 헤더, 다른 사이트에서 시작한 변경 요청, 만료된 세션을 거부합니다. 로그인 세션 쿠키는 HttpOnly이고 8시간 후 만료됩니다. OAuth 콜백을 위해 SameSite=Lax를 사용합니다. 로컬 HTTP 주소를 인터넷에 프록시하지 마세요. 브라우저의 모든 POST는 같은 origin이어야 합니다.

서버는 COROS의 공인 게이트웨이에서 발급자와 엔드포인트를 찾아 HTTPS, COROS 도메인 및 같은 리전을 확인한 다음 PKCE S256과 무작위 state를 사용합니다. OAuth 접근·갱신 토큰은 서버 메모리에만 보관하므로 재시작 후 자동 갱신을 사용하려면 다시 승인해야 합니다. 서버가 목록에서 확인한 읽기 도구만 호출합니다. COROS 앱에 일정을 변경하거나 쓰는 호출은 없습니다.

Windows에서는 요약 데이터와 개인 설정을 DPAPI의 CurrentUser 범위로 암호화합니다. 사용자에게 전달된 작업 폴더에서는 저장소 밖의 `work/private-coros.dpapi`와 같은 위치의 `.prefs` 파일을 사용합니다. 독립 체크아웃은 Windows LocalAppData의 `CorosDashboard` 폴더를 사용합니다. `COROS_PRIVATE_CACHE`로 저장소 밖의 파일을 지정할 수 있습니다. 다른 OS에서는 토큰·데이터·설정을 이 프로세스의 메모리에만 보관합니다. 서버는 `dist/`의 정적 파일만 제공합니다.

## 데이터 범위

| 항목              | 조회 및 표시                                                                                                                                                                                                                       |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 운동 목록         | 최근 90일의 최대 100건. 거리·운동 시간·심박이 반환된 경우 표시                                                                                                                                                                     |
| 상세 기록         | 공식 세션 상세의 훈련 부하·유산소·무산소 효과와 검증된 단위의 랩 그룹. 최근 러닝을 우선 조회하며 웹 승인 후 개별 열람 시 FIT 1건에서 반환된 GPS·페이스·심박·케이던스를 메모리에서 해독. 원본 다운로드에는 COROS 일일 한도가 적용됨 |
| 수면              | 기상일 기준 합계 시간·점수·단계별 비율 및 일일 건강 도구에서 돌아오는 깊은 수면·얕은 수면·REM 시간. 시각별 수면 단계 원본은 현재 조회 결과에 없어 임의 복원하지 않음                                                               |
| HRV·심박·스트레스 | 최근 30일 중 데이터가 있는 날짜. HRV는 공인 일평균값만 사용                                                                                                                                                                        |
| 훈련 부하         | COROS 단기·장기 부하와 개별 세션의 부하를 서로 다른 필드로 유지                                                                                                                                                                    |
| 회복·체력         | 현재 회복률·VO₂max·역치 페이스·예상 대회 기록                                                                                                                                                                                      |
| 일정              | 조회일 15일 전부터 31일 후까지의 공식 일정. 자체 계획은 사용자 설정에 별도 저장                                                                                                                                                    |

운동 목록의 가공된 표시용 시간, 비율, 상태 메시지는 COROS의 영문 텍스트로 반환될 수 있습니다. 단위나 필드를 인식하지 못하면 값을 비워 둡니다. 툴별 오류는 `warnings`에 남기며 모든 읽기가 실패하면 이전 스냅샷을 유지합니다. 한국 시간으로 조회 기간을 정하며 건강 자료는 COROS가 보고한 기상일을 보존합니다.

## HTTP 인터페이스

| 경로                                         | 기능                                          |
| -------------------------------------------- | --------------------------------------------- |
| GET /api/status                              | 소유자 로그인 이후 연결·캐시·동기화 상태 확인 |
| POST /api/login                              | JSON의 password에 터미널 로그인 코드 전송     |
| GET /api/data                                | 현재 소유자의 COROS 데이터                    |
| POST /api/connect                            | 소유자가 직접 열 COROS OAuth URL 반환         |
| GET /api/callback                            | OAuth redirect URI, 세션·state·만료 확인      |
| POST /api/sync                               | 허용된 데이터 동기화                          |
| POST /api/activity                           | JSON의 id로 해당 스냅샷 안의 운동 상세 조회   |
| GET /api/preferences · POST /api/preferences | 웹앱 목표·자체 계획 전체 조회·갱신            |
| POST /api/logout · POST /api/disconnect      | 소유자 세션 종료 · 서버 연결과 데이터 삭제    |

## 확인

`node server/check.mjs`를 실행하면 임시 디렉터리·합성 데이터로 보안 및 저장 동작을 확인합니다. 4178 포트가 비어 있어야 합니다. OAuth 토큰 교환과 MCP 통신 규약은 이 검사에서 모의 응답을 사용합니다. 실제 연결은 본인 브라우저의 승인이 필요합니다.

이 작업에서는 연결된 COROS 커넥터의 실제 읽기 도구를 확인하고 공식 게이트웨이에서 로컬 콜백의 클라이언트 등록과 PKCE 승인 URL 생성을 검증했습니다. 웹앱의 OAuth 자격 증명은 대화에 연결된 커넥터와 별개입니다. 웹 로그인 후의 토큰 교환과 갱신은 본인의 COROS 승인이 필요합니다.
